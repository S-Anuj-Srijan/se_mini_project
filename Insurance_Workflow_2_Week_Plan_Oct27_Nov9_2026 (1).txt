DAILY GIT AND JIRA RULES
1. Create a Jira story/task/bug with acceptance criteria, owner and estimated story points BEFORE starting.
2. Move it To Do -> In Progress -> In Review -> QA -> Done as evidence supports.
3. Create one branch per Jira issue: feat/INS-KEY-short-name, test/INS-KEY-short-name, fix/INS-KEY-short-name.
4. Commit logical working changes; sample messages below are plans, not quotas or a claim work happened. Include actual Jira issue key after creation.
5. Push the branch and open a PR with issue link, summary, test evidence and screenshots as appropriate.
6. CI: formatting/lint, unit tests and meaningful API checks; expand to DB integration/security once available. Require a passing check and at least one OTHER contributor's review before merge.
7. Use protected main; no direct feature pushes, fabricated commits, or self-approval. Record merge SHA, actual test result, and daily blocker.
8. Each day's closure: Jira statuses/remaining SP, PR URLs, commits, CI result, demos or screenshots, problems and next steps.
