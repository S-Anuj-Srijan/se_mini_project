1. SCOPE AND NON-GOALS
----------------------
Build a small multi-page, frontend-only insurance workflow *demonstration*.
Use Node.js only to run Vite's development/build tooling. The browser runs
plain HTML, CSS, and JavaScript. NO Node.js application server is needed.

Stack: Node.js + Vite + plain HTML + plain CSS + vanilla JavaScript.
No React, Express, TypeScript, Flask, database, real authentication, API,
file storage, emails, payment, deployment infrastructure, or Docker.

Important distinction:
- FIRST, Codex sets up only the scaffold. All HTML <body> elements remain
  EMPTY; CSS and JS remain EMPTY. No visible UI, mock data or page content.
- THEN, team members implement frontend pages in their own PRs over the sprint.
- Any login, application status, or approval behavior is visual/simulated,
  NOT secure or persistent server-side insurance processing.
- Do not describe a simulated feature as a functioning backend feature.

Pages to exist in the scaffold:
  index.html             (landing / navigation, to be built later)
  login.html             (demo sign-in screen, later)
  dashboard.html         (overview, later)
  application.html       (new application form, later)
  applications.html      (applications list, later)
  staff.html             (staff review screen, later)

Expected repository:
  index.html
  login.html
  dashboard.html
  application.html
  applications.html
  staff.html
  css/style.css
  js/main.js
  package.json
  package-lock.json
  vite.config.js         (for six-page build)
  .gitignore
  README.md

3. SIMPLE COLLABORATION RULES
-----------------------------
A. Anuj creates the GitHub repo and grants collaborators appropriate access.
B. Anuj creates or assigns a Jira issue BEFORE work begins.
C. Each contributor creates a new branch from up-to-date main, e.g.:
      git switch main
      git pull
      git switch -c feat/IWM-12-login-page
   Replace IWM-12 with the real Jira issue key.
D. Contributor edits ONLY the files needed for the assigned task.
E. Contributor tests the change locally:
      npm install       (first setup only)
      npm run dev
      npm run build
F. Contributor commits and pushes:
      git add <specific-files>
      git commit -m "IWM-12: create login page"
      git push -u origin feat/IWM-12-login-page
G. Contributor opens a PR describing purpose, touched files, how tested,
   and screenshots once the page contains UI.
H. Anuj reads the Files changed tab, checks scope, runs build, requests
   corrections when necessary, and merges only after a genuine review.
I. Jira: To Do -> In Progress -> In Review -> Done, as evidence supports.
J. Protect main with PR review requirements where repository settings permit.
   GitHub configuration and access must be done separately from scaffolding.

Every day record: Jira issue key, owner, branch, commit SHA, PR link,
reviewer, build result, actual progress, blockers, and next step.
Do not invent commits, CI outcomes, screenshots, or completed tasks.
